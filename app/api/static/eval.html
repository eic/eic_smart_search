What the metrics mean
  • Right source found (hit rate): the benchmark defines, for every question, which page/record a correct answer must come from — this counts how often it appears in the top results. Deterministic, no AI judging involved.
  • Answer contains the expected fact: for questions with a known factual answer (a number, a name, a link), the generated answer must literally contain it.
  • Rank of right source (MRR): how high the right source ranks (1.0 = always first).
  • Judge scores (1–5): a separate LLM grades each answer for relevance, faithfulness to the cited sources, and completeness.
  • Benchmark: real user questions with manually verified expectations (see Benchmark questions below). A question is added whenever a real query fails — the benchmark grows harder over time.

How this is measured
  • nDCG@5 — rank-aware quality of the top 5 sources, scored against an ideal top-5 that is entirely on-target: finding the right page first beats finding it fifth, and padding the list with off-topic chunks costs points. Headline number.
  • Hit rate — the right page appeared anywhere in the returned sources.
  • precision@5 — share of the top 5 sources that are on-target. A benchmark question can have several acceptable sources, so this, not recall, is the coverage measure.
  • Confidence interval — 2 000-sample bootstrap over the questions. With a benchmark this size, differences smaller than the interval are noise.
  • p-value — paired bootstrap against the first row of each block (the same questions, both configurations), the standard IR significance test.
  • Answer generation is disabled for retrieval arms, so no LLM randomness enters these numbers; the LLM block is opt-in and judged separately.
  • In the LLM block, trust “expected fact in answer” first — it is a literal string check. The judge is itself an LLM from the same family as one of the candidates, so its grades can mildly favour that candidate.
